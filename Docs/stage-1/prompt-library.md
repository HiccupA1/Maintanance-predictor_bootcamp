# Prompt Library

## Requirements discovery

> Extract confirmed functional requirements, non-goals, assumptions, open questions, and traceability from the source PRD. Do not invent behavior where the PRD is silent.

## UX design

> Convert confirmed personas and user stories into accessible, role-aware screens and end-to-end journeys. Preserve open decisions as explicit design placeholders.

## API implementation

> Implement the documented contract using the existing router → service → repository → model layering. Include validation, structured problem responses, correlation IDs, and OpenAPI metadata.

## QA

> Derive positive, negative, boundary, authorization, state-transition, and persistence tests from the API contract. Record actual evidence, severity, and release impact.

## Release review

> Check documentation, migrations, environment configuration, API readiness, frontend quality, smoke tests, rollback steps, and unresolved P0/P1 defects before recommending Go.
